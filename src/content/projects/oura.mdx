<SectionTitle>Ten Heuristics, One App</SectionTitle>

I reviewed the current Oura app against Nielsen’s ten usability heuristics, to see where it already works and where people get stuck.

<HeuristicCards
  items={[
    {
      title: 'Visibility of status',
      question: 'Do you know where you are in the system and where you can go next?',
      example: 'Elevator buttons lighting up',
      findings: [
        'The bottom navigation bar (Home, Readiness, Sleep, Activity) gives a sense of where you are.',
        'The Home screen gives a daily overview of your current status, helping users feel oriented.',
        'Each section, like Sleep, has a consistent header and back button.',
      ],
    },
    {
      title: 'System vs. real world',
      question: 'How similar are the digital and physical experiences?',
      example: 'Shopping carts on a website vs. in a store',
      findings: [
        'The ring is very intuitive and needs no interaction. The app, by contrast, can feel overwhelming and data-heavy, especially for first-time users.',
        'There’s a **disconnect between the passive ring and the active app**, where you have to navigate charts, scores and insights to get value.',
      ],
    },
    {
      title: 'User control and freedom',
      question: 'Does the user get lost in the experience at any time?',
      example: 'Back buttons; the ability to edit a shopping cart',
      findings: [
        'Deeper views, like past trends, heart rate graphs or tags, **aren’t always easy to find or return from.** You can end up buried in a chart and unsure how you got there.',
        'Too much data without context or priority can overwhelm newer users, who see dozens of metrics without knowing which matters most today.',
      ],
    },
    {
      title: 'Consistency and standards',
      question: 'Does the system follow patterns?',
      example: 'Buttons in the same place; no new functionality introduced mid-experience',
      findings: [
        'Button placement is mostly consistent. The fixed bottom navigation bar means users always know how to return to the main areas.',
        'The card layout for each data point (Sleep, HRV, Activity) repeats across screens, so users learn it once and apply it everywhere.',
      ],
    },
    {
      title: 'Error prevention',
      question: 'How is the system designed to avoid mistakes?',
      example: 'Similar features grouped together',
      findings: [
        'Most of the app is read-only, so **users mainly review data rather than enter it**, which greatly reduces mistakes.',
        'Tags like “stressed,” “caffeine” and “travel” offer no suggestions or clarification, so users may choose inconsistent tags that skew long-term trends.',
      ],
    },
    {
      title: 'Recognition rather than recall',
      question: 'Is there enough information on the surface to know where you’ll go next?',
      example: 'Breadcrumbs, onboarding, pagination',
      findings: [
        'There’s no breadcrumb navigation, so users can feel lost or unsure how they ended up in a view.',
        'There’s no “you are here” indicator, and **no way to jump between related views**, like Sleep to Readiness, without backing out completely.',
      ],
    },
    {
      title: 'Flexibility and ease of use',
      question: 'Does the experience differ between novice and expert users?',
      example: 'Keyboard shortcuts; shortcuts for efficiency',
      findings: [
        '**Yes, it differs between users.**',
        'Novices can feel overwhelmed by terms like HRV, latency and body temperature deviation, and don’t know which score matters or what to do when Readiness is low.',
        'Experts navigate with confidence, toggle between days, weeks and months, and know how each metric applies to them.',
      ],
    },
    {
      title: 'Aesthetics',
      question: 'Can you strip the screen down to its main components?',
      example: 'White space, simplicity',
      findings: [
        'Yes, overall. The type is very simple.',
        '**The contrast between navy and dark navy is too subtle**, making sections hard to tell apart for older users. Stronger contrast would improve readability.',
      ],
    },
    {
      title: 'Help users find errors',
      question: 'Are mistakes easy to identify?',
      example: 'Toast notifications, red Xs vs. green checkmarks',
      findings: [
        'Green checkmarks and blue-highlighted buttons signal positive actions, like “Sync complete.”',
        'Red appears in some areas, like low Readiness or sleep quality, but as a cue for low scores rather than error states.',
      ],
    },
    {
      title: 'Help and documentation',
      question: 'Can users learn how to navigate the experience if needed?',
      example: 'FAQs, a help assistant, contact info',
      findings: [
        'Yes, users can learn and navigate the experience.',
        'It takes a while to learn all the features, because some are tucked away.',
        'There’s **no real FAQ or help assistant**, which is why an AI guide would be so helpful.',
      ],
    },
  ]}
